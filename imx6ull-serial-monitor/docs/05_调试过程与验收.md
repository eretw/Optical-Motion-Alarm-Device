# 调试过程与验收

按层定位，每一层留下证据再往下走。所有板端命令都应在真实开发板Linux执行。

## 第1层：电脑程序与协议

```powershell
py -3 -m unittest discover -s tests -v
py -3 host\monitor.py --simulate --seconds 12
```

能握手、看到样本、设置合法阈值；设置周期1ms应被拒绝；产生告警后SQLite中有记录。未构建C测试DLL时会明确skip，不能把跳过当作C通过。交付测试报告注明实际结果。

## 第2层：CH340与串口终端

设备管理器确认真实COM端口。关闭VirtualBox USB捕获、串口监测程序及其他终端，确保只有一个电脑程序打开它。115200 8N1、无流控，复位看日志。

| 现象 | 优先检查 |
|---|---|
| 找不到COM | USB_TTL、数据线、电源、CH340驱动、虚拟机捕获 |
| COM1/COM2但不出板卡日志 | 是否只是ELTIMA软件虚拟串口 |
| Access denied / 端口占用 | SecureCRT、GUI、CLI、虚拟机是否仍占用 |
| 全是乱码 | 波特率、帧格式、是否正在把二进制协议当文本看 |
| 只有U-Boot没有Linux | bootcmd、内核/DTB路径、root分区、控制台参数 |
| 连终端完全无字 | 启动拨码、JP5、供电、USB接口；先排查再刷机 |

## 第3层：真实板端应用 + mock

先执行 `scripts/board-info.sh` 保存架构、内核、挂载、输入设备与console信息。用`run-session.sh --mock`启动。PC HELLO应返回`monitor/1 mock`。此阶段验证真正的UART链路、二进制协议、线程与磁盘，不需要传感器。

如果PC握手超时，恢复终端后查看：

```sh
cat /var/lib/serial-monitor/session.log
ps
cat /proc/cmdline
```

文件存在却提示`not found`可能是动态加载器缺失，不只代表路径错误；`Exec format error`通常是架构不对；`Permission denied`检查可执行位与挂载noexec。检查应用的ARM ELF类型，勿传入Windows exe或x86 Linux程序。

临时会话会把内核printk降级，严重日志仍能插入；看见CRC错误与日志夹杂先查console所有权。板端另一个getty读走数据时，CRC正常也可能收不到完整命令。不要靠增加超时掩盖串口争用。

## 第4层：设备树与驱动

```sh
uname -r
dmesg | tail -n 50
ls /sys/bus/i2c/devices
ls /sys/bus/spi/devices
ls -l /dev/mon_*
```

`Invalid module format`：核对vermagic、配置、编译器与Module.symvers。`probe`不执行：查实际加载DTB的compatible、status、控制器是否注册。SPI WHO_AM_I=00/FF：查片选、时钟、模式0、pinctrl、节点reg与硬件连接。I2C报ENXIO/EIO：查0x1e地址、复用、供电和总线控制器。

不要在驱动已经绑定、正在采样时无差别运行i2c探测/写寄存器工具。用日志与明确寄存器读做定位，避免改变芯片状态。

应用可读取6字节AP数据和14字节IMU数据；任何短读或错误会使valid=0。0也是合法测量值，不能把“读失败”统一写成0再当正常样本。

## 第5层：功能验收

| 操作 | 预期结果 | 保存证据 |
|---|---|---|
| 正常静置 | 连续有效数据，无高频误报 | CSV、状态截图 |
| 遮挡/照亮光传感器 | ALS变化，阈值越界生成一次事件 | SQLite事件、PC日志 |
| 缓慢晃动板子 | motion变化，越界告警 | 原始XYZ和时间戳 |
| KEY0/PC消音 | 当前周期蜂鸣器关闭；事件仍保留直到PC送达确认 | GPIO/按键测试记录 |
| 修改阈值后重启应用 | STATUS返回保存的值 | config文件、查询结果 |
| 关闭PC客户端再制造告警 | 板端持续采集，待确认事件增加 | event-*文件 |
| 重新打开PC连接 | 事件补传，SQLite去重，确认后板端文件删除 | 双端记录 |
| 停止PC处理/拔USB_TTL | 内存不随断开时间无限增长；计数可解释 | /proc/PID/status、STATUS |
| 降低阈值反复制造事件 | 容量上限生效，满时计数递增 | dropped/storage_errors |
| --stop或300秒超时 | 应用退出，蜂鸣器关闭，终端恢复 | 串口会话日志 |

拔USB_TTL时必须确保开发板仍由独立电源供电，否则测试的是掉电而不是断线。USB_TTL断线在板端UART未必产生POLLHUP，靠心跳识别会话失联。模拟模式重连会新建模拟器；不能用它证明真实板端的跨连接或跨断电补传。

## 第6层：长时间与故障测试

24小时是待执行的验收目标，不是本次已完成的结果。每隔一分钟采集`top`、`/proc/PID/status`、`/proc/PID/fd`数量、事件数量与磁盘剩余空间。关注RSS持续增长、FD增长、采样间隔长尾、磁盘满、sensor_errors和storage_errors。

写满测试应在专门的小容量测试文件系统中做，避免填满系统根分区。掉电测试应先备份；保证“已完成持久化的事件重启后仍存在”，不要宣称能保证RAM中未落盘样本。

## 调试工具怎么用

- `dmesg`：probe失败、中断、总线、模块错误。临时会话期间日志仍在环形缓冲区，可退出后查看。
- `strace -f -tt -o /tmp/monitor.strace ...`：read/write/poll是否阻塞、返回值和线程行为。串口会话内把跟踪写文件。
- `gdb/gdbserver`：段错误、线程栈、共享状态。只用一个USB_TTL时不能同时运行业务协议与传统同串口gdbserver会话；先暂停业务并换调试通道，或保存core后在主机交叉GDB分析。
- `ulimit -c unlimited`：在允许core的系统上启用core，确认core_pattern与存储空间；保留对应带符号二进制。真实rootfs可能没有gdb/strace，需先加入Buildroot或拷贝兼容版本。
- `cat /proc/interrupts`：查看KEY0对应中断计数；应用使用evdev，事件编号需核实。
- 示波器/逻辑分析仪：验证UART波特率、I2C ACK和SPI片选/模式，软件日志不能替代电气检查。
