# 串口通信协议 v1

物理参数固定：115200 baud，8N1，无 RTS/CTS，无 XON/XOFF。约 11520 字节/秒的理论单向上限，还需扣除帧开销与实现延迟。每秒5个约200字节遥测帧足以演示，不能照搬到高速振动原始波形。

| 偏移 | 长度 | 字段 |
|---|---:|---|
| 0 | 2 | magic：A5 5A |
| 2 | 1 | version：01 |
| 3 | 1 | type |
| 4 | 2 | sequence，小端 |
| 6 | 2 | payload length，小端，0～256 |
| 8 | N | payload |
| 8+N | 2 | CRC，小端 |

CRC16/CCITT-FALSE：poly=0x1021，init=0xFFFF，refin=false，refout=false，xorout=0。覆盖从 version 到 payload，不含 magic 和 CRC 自身。标准校验串 `123456789` 的值为 0x29B1。

| type | 方向 | 载荷 |
|---|---|---|
| 01 HELLO | PC→板 | 空；板回版本与mock/hardware |
| 02 CONFIG | PC→板 | ASCII `200,3000,4000`，分别是周期ms、光照raw阈值、运动raw阈值 |
| 03 SILENCE | PC→板 | 空；当前告警周期消音 |
| 04 STOP | PC→板 | 空；退出板端应用，供调试恢复终端 |
| 05 EVENT_ACK | PC→板 | ASCII事件ID，16位小写hex、连字符、8位小写hex |
| 06 STATUS | PC→板 | 空；查询配置、积压和错误计数，同时心跳 |
| 80 REPLY | 板→PC | JSON；sequence与请求相同，含ok及错误原因 |
| 81 SAMPLE | 板→PC | JSON；最新采样、alarm、valid、dropped、sensor_errors |
| 82 EVENT | 板→PC | JSON；id、ms、als、motion |

命令参数范围：200≤period≤10000、0≤light≤65535、1≤motion≤65535。拒绝符号、空白、超长数、溢出、尾随内容、内嵌NUL。配置一次更新三个值，避免一条命令只改了一部分。

示例采样：

```json
{"ms":123456,"als":120,"ax":0,"ay":0,"az":16384,"gx":0,"gy":0,"gz":0,"motion":20,"valid":1,"alarm":0,"dropped":0,"sensor_errors":0}
```

`ms` 是板端 CLOCK_MONOTONIC 启动时间，不是北京时间；PC另外记录本地接收时间。

## 异常处理

- 每次 read 不等于一帧。状态机逐字节处理拆包、多帧合并、无关启动日志。
- version/length错误时丢一个字节继续找magic；CRC错也逐字节重新同步。
- 半帧持续超过1秒没有新字节，丢弃残帧。注意持续噪声制造的伪造合法长度可延迟重新同步，不能宣称任意噪声下零丢帧。
- PC请求默认2秒超时，显示错误；用户可重试。CONFIG设置绝对值、SILENCE、EVENT_ACK是幂等操作。未实现命令事务历史缓存和自动重试。
- PC每2秒发送STATUS；板端6秒没有合法请求后停止实时上报，但继续采集/记录；PC7秒未收到合法帧报告断开。重新连接需要HELLO。
- 传输序号16位循环，只用于连接内请求关联；告警去重使用持久事件ID，不能拿短序号当全局唯一编号。
- 本地串口属于可信物理链路假设，CRC是差错检测而非认证。本协议没有加密/用户鉴权。
