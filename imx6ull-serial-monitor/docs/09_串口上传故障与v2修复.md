# 串口上传 v1 失败与 v2 修复

用户实物输出已确认：板端`serial-monitor-upload.b64`为1,503,907字节，目标`serial-monitor-board.tar.gz`不存在。对应电脑部署包为1,260,099字节；v1按76字符换行发送的Base64文本应为1,702,239字节，差198,332字节。因此这次传输不完整，不能解压安装。

v1通过交互shell一次接收长heredoc，连续发送时没有逐块接收确认；显示Sent只代表电脑端完成写入调用。原脚本也只等成功标记，未显示板端错误。具体丢失发生于UART缓冲、TTY或交互shell的哪一环节，当前截图尚不能确定。

## v2 的改动

- 使用前台非交互`sh`接收，临时关闭终端回显和规范行模式，保留Ctrl+C中断能力。
- 默认每块1024字节，由`dd bs=1 count=N`读取明确长度，再确认文件块长度并追加。
- PC只有收到完整的当前块ACK行后才发下一块，不把回显命令里的标记误当ACK。
- 最后一块后解码到`.part`文件；只有SHA256通过才替换最终部署包。
- 收到明确失败标记立即停止；超时显示最近板端输出，完整收包日志存入PC的`logs/upload-MON_*.log`。
- 通过shell trap恢复终端设置；异常时PC尝试发送Ctrl+C终止接收。
- 新增7项上传测试；与原测试合计21项通过。它们是电脑上的模拟传输与协议测试，不代替真实串口验证。

## 当前用户重试步骤

开发板已在root shell。先输入`stty sane`，再按Ctrl+]退出miniterm回到Windows PowerShell：

```powershell
cd 'D:\linux项目\imx6ull-serial-monitor'
py -3 host\upload.py --port COM13
```

新版首先打印`Upload v2`，进度为`Board acknowledged ...`。此时不要同时打开其他串口工具，不复位/断电。

成功应打印`Upload SHA256 verified:`及哈希。当前部署包的SHA256为：

```text
5938e162b25d18fac149ab4e1c2d0fd654b2b16c4edd6b9115886e527928ddb5
```

本次修复没有改变ARM部署包，因此该哈希不变。v2的Base64文件不额外插入换行，完整文件长度应为1,680,132字节，和v1的1,702,239字节不同。

如果再次失败，把新版最后错误和`logs/upload-MON_*.log`提供出来。若终端没有提示符，重新打开后按Ctrl+C、回车，再执行`stty sane`。新版不会在失败时自动安装或刷写系统。
