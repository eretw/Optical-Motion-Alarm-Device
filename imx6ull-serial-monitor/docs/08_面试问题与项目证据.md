# 面试问题：用代码与实验回答

不要把本项目描述为已经量产或经过长期现场验证。先复现实验，再填入自己的数据。

| 方向 | 常见问题 | 在项目里怎样回答/验证 |
|---|---|---|
| C基础 | volatile能替代线程锁吗？ | 不能；共享结构由mutex保护，退出标志使用要求lock-free的C11 atomic |
| C基础 | 有符号16位数、大小端怎么处理？ | sensors.c显式从字节组装，不能直接把任意字节指针转short* |
| C基础 | 为什么不用无边界sprintf/atoi？ | 限长snprintf；strtoul+errno+尾字符检查，测试超大整数 |
| C基础 | 堆、栈、静态变量分别在哪里？ | 栈上小帧缓冲，静态共享状态，系统库可能内部申请堆；解释线程各有栈 |
| 系统启动 | DDR何时初始化？ | 在Linux正常运行前由平台启动链完成；结合本板ROM/DCD/U-Boot方案查源码，不能把所有板都说成SPL |
| 系统启动 | U-Boot、内核、设备树、rootfs区别？ | 对照MfgTool启动阶段和最终eMMC镜像，解释普通monitor ELF不是bootloader镜像 |
| 系统启动 | 为什么Starting kernel后没字？ | 可能是console错误、DTB/内核不匹配或内核未启动，不能只看无输出断言死机 |
| 交叉编译 | x86电脑如何编译ARM程序？ | build-windows.py/Makefile，查看ELF machine=ARM、EABI、硬浮点及动态加载器 |
| 驱动模型 | compatible如何匹配？ | DTS片段对应两个of_device_id表；故意改错一个compatible观察probe不执行 |
| 驱动模型 | platform和I2C/SPI驱动区别？ | 总线控制器常走platform，AP/IMU挂在I2C/SPI总线；本项目无需把所有设备都写成platform |
| 字符设备 | open/read如何到内核？ | misc注册得到设备节点，read进入sensor_ops，copy_to_user后返回实际长度 |
| 字符设备 | read返回0、负值、正值各表示什么？ | 0通常EOF，负值内核转errno，正值实际字节；本项目不允许复制后错误返回0 |
| 驱动并发 | mutex与spinlock如何选择？ | I2C/SPI调用可能睡眠，用mutex；不能持spinlock做睡眠型总线访问 |
| 资源生命周期 | unbind后已有FD怎么办？ | 静态驱动对象仍存在，ready=false，锁保护总线指针，后续read返回ENODEV |
| 设备树 | reg为什么有时是地址有时是片选？ | I2C reg=0x1e是从机地址；SPI reg=0是片选序号；由父总线binding决定 |
| GPIO/中断 | KEY0如何消抖、如何到用户态？ | gpio-keys处理IRQ/消抖，evdev事件由应用读取；对照proc/interrupts与input事件验证 |
| I2C | 为什么读取寄存器用两个msg？ | 写寄存器地址后读数据，I2C框架组织combined transfer；检查i2c_transfer返回msg数 |
| SPI | CPOL/CPHA、片选、速度如何决定？ | ICM模式0，控制器管理GPIO片选，最大8MHz；示波器/逻辑分析仪验证 |
| UART | 波特率/8N1为什么影响有效带宽？ | 每字节至少10bit，115200约11520B/s，协议头和CRC进一步消耗带宽 |
| IO模型 | read一次为什么不等于一帧？ | 串口也是字节流，用分片测试、连帧测试和协议状态机说明 |
| IO模型 | 非阻塞read返回EAGAIN怎么办？ | 等待poll而不是忙循环；写操作处理短写与超时 |
| 多线程 | 单核为什么需要锁？ | 抢占和IO阻塞可在任意执行点切换；单核并不消除读改写竞争 |
| 多线程 | 为什么不把磁盘IO放进锁里？ | fsync可慢，锁内只复制状态，否则采样被磁盘阻塞 |
| 多线程 | 生产快、消费慢怎么办？ | 最新样本覆盖；告警有界队列；容量满可观察地丢弃而不是无限malloc |
| 协议 | CRC和加密有什么区别？ | CRC用于检测差错，不能抵抗恶意伪造；此版本假定本地可信串口 |
| 协议 | 断开USB为什么板端write还可能成功？ | 板端写的是SoC UART缓冲；CH340是否接电脑不一定反馈给UART，因此用心跳 |
| 协议 | ACK丢了会怎样？ | 板端重传相同事件ID；PC主键去重后再次ACK |
| 协议 | 为什么不用16位帧序号做全局去重？ | 序号会回绕且重启重置；采用随机启动标识+事件计数并持久化 |
| 文件系统 | write/flush/fsync/rename区别？ | write进入内核缓存，stdio flush清用户缓冲，fsync请求持久化，rename替换名字，目录也需同步 |
| 文件系统 | rename成功后就一定掉电安全吗？ | 还要考虑目录同步、文件系统和介质；故障报告不能把不确定状态说成成功 |
| 异常处理 | 一次读失败为什么不填0？ | 0是正常数值；valid字段和错误计数保留错误语义 |
| 调试 | 内存泄漏/FD泄漏怎么看？ | 长时采集RSS与/proc/PID/fd，区分缓存、持续增长、队列容量 |
| 调试 | 段错误怎么定位？ | 保存同构建符号与core，查看回溯；驱动错误另看dmesg/Oops，不能混为一谈 |
| 系统设计 | 为什么先复用gpio-leds/input？ | 标准接口减少重复造轮子和资源冲突；传感器阶段再讨论IIO改造 |

## 面试时可以现场演示的三条链路

1. 参数：PC CONFIG → CRC校验 →范围校验→原子保存→ACK→STATUS查询→重启后仍生效。
2. 告警：真实传感器→阈值越界→蜂鸣器→事件落盘→PC提交SQLite→确认删除→重复事件不重复入库。
3. 故障：关闭PC→板端继续采集→观察有界缓存→重新握手补传→解释容量满时的实际策略。
